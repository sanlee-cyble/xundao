# 字段库、采集器与模型运行时闭环

当前运行时已经按“模型理解、程序执行”的原则形成闭环。Excel 进入系统后，确定性表头规则先解析场景、内容类型、周期、流量和视图；未命中旧字段注册表时，再用蒲公英原生名称匹配字段合同库。只有仍存在多个合理候选时才调用 Qwen，且工具参数中的 `capabilityId` 枚举由本次字段库候选动态生成，模型不能创造字段、接口或口径。

任务确认和开始采集前均执行同一套严格准入校验：字段必须具备完整维度，属于已经与蒲公英前端对齐的能力项，并具有确定性请求定义和响应 JSON 路径；仅在接口中观察到、尚未完成前端对齐的字段会停在澄清状态。蒲公英链接、小红书主页链接、万粉换算、赞藏中位数和近 16 篇最高值等已有确定性执行器单独登记，不会被误当成模型推断。

采集器按字段合同编译请求，保存请求签名、接口、参数、传输方式、HTTP 状态、采集时间和字段值状态。`0`、无样本、请求失败和权限问题不再共用空白语义；任务检查点同时保存 `contractValues` 与 `contractProvenance`，恢复任务时继续沿用同一请求签名和证据链。

DeepSeek 只处理 Excel 中无法直接从蒲公英取值、且允许基于证据概述的字段。每一行输入同时携带扁平证据和结构化证据包；模型必须引用存在且状态为 `VALUE` 或 `ZERO` 的 `evidenceKeys`。程序逐单元格检查引用、字数、禁止推断词、业务事实保护和口径表达，通过后标记为 `MODEL_ACCEPTED`；不通过的单元格单独留空，不会清空同一行其他字段。模型不可用时，已有确定性摘要规则只使用同一证据包生成内容，合作、授权等事实字段始终进入人工填写。

每个输出单元格现在都有 `cellEvidencePackages`：蒲公英字段记录字段合同键、能力 ID、请求签名和值状态；模型字段记录生成方式、审核状态和引用的证据包；人工字段记录 `MANUAL_REQUIRED`。Excel 仍只写业务需要的值，完整证据保留在任务结果和检查点中供恢复、审计与异常定位。

本轮离线回放 2026-07-31 的真实蒲公英响应，日常笔记、图文+视频、近 30 日、全流量请求成功提取中位评论量 `38`、互动率 `0.026`、阅读来源搜索页 `0.551`，三个字段均保留同一真实请求签名并进入推荐理由证据链。自动化发布基线为 105 项全量测试和 73 项集成测试。
