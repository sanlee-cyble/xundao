# 蒲公英字段合同库 V1

字段合同库 V1 的目标不是给寻达自定义一套指标名称，而是把蒲公英达人“笔记主页”中可证明存在的数据转换成可执行、可校验、可追溯的取数合同。

当前版本由 2026-07-31 的真实登录态采集证据生成，覆盖 25 个目标口径、44 个去重成功请求和 379 个接口能力项。其中 62 个能力项已经与蒲公英前端名称及交互路径对齐，状态为 `pgy_ui_verified`；其余 317 个能力项已经在接口响应中观察到，但尚未逐项完成前端名称与路径校准，状态为 `api_observed_needs_ui_alignment`，系统不得自动把它们宣称为可直接交付字段。

每项合同至少记录：

- 蒲公英原始名称、所属数据域和前端路径；
- 日常/合作、图文/视频/图文+视频、30/90 天、全流量/仅自然流量和数据视图；
- 确定性请求方法、接口、参数模板；
- 响应 JSON 路径、数据类型和输出形态；
- 单位以及 0、`null`、字段缺席的不同语义；
- 合同版本、现场证据时间、平台数据更新时间和校准状态。

执行门已经接入任务确认、任务启动和采集计划编译三个运行时位置，遵循以下规则：

1. `pgy_ui_verified` 且所有口径维度完整的字段可以编译为采集请求。
2. `api_observed_needs_ui_alignment` 字段只能作为字段扩展候选；完成蒲公英前端校准或任务级人工确认后才能执行。
3. 缺少业务属性、内容类型、周期、流量范围或视图的合同不能进入采集。
4. 采集值由程序通过合同中的 JSON 路径读取并原值写入，模型不得改写蒲公英原始值。
5. `0` 必须保留，`null`、字段缺席、权限不足和请求失败必须使用不同状态。
6. Qwen 只能从当前字段库候选的 `capabilityId` 白名单中选择；不能创造字段、接口或口径。
7. 每个采集值保存字段合同键、请求签名和值状态，并作为 DeepSeek 单元格审计的证据包。

主要文件：

- `config/pgy-field-contracts.v1.json`：机器可读的字段能力和证据目录；
- `config/pgy-field-schema-snapshot.v1.json`：从现场全量 JSON 脱敏得到的可复现字段结构快照；
- `scripts/build_pgy_field_contracts_v1.mjs`：从全量实时响应重新生成合同库；
- `src/pgy_field_library_v1.mjs`：字段查询、原生名称匹配、合同实例化、执行校验和 JSON 路径读取；
- `src/field_registry.mjs`：兼容现有任务的字段 ID，并把已确认字段升级为 V1 合同；
- `src/collection_plan.mjs`：把合同编译为请求并按响应路径确定性取值。
- `src/field_resolution_service.mjs`：生成字段库候选并限制 Qwen 的选择范围；
- `src/field_execution_gate.mjs`：在确认、启动和编译前阻止未对齐或不可执行字段；
- `src/cell_evidence_service.mjs`：生成逐单元格证据包和模型决策溯源。

当前兼容字段层已经覆盖 421 个蒲公英字段变体，包括评论中位数、分享中位数、互动率、曝光来源、阅读来源以及仅自然流量下的曝光、阅读、互动和成本指标。下一轮工作应以 317 个待校准能力项为清单，逐项核对蒲公英前端名称、位置、适用条件和展示单位，再转为 `pgy_ui_verified`。
